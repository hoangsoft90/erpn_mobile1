## 3. M1 — TRẦN OUTPUT khi giải nén (đo A/B trên CÙNG file, 2 tiến trình)

```
TRƯỚC (inflateSync KHÔNG trần): nén 19.543 B -> phình 20.000.000 B,  57 ms, RSS +49,1 MB
SAU   (maxOutputLength = 8 MB) : nén 19.543 B -> TỪ CHỐI theo tên,   19 ms, RSS  +8,5 MB
Mã lỗi: EINVOICE_PDF_INFLATED_TOO_LARGE  (HTTP 413)
(§9.5 đo bản nặng hơn: 106.884 B -> 31.457.284 B, 294x, 4,3 s, RSS +541 MB)
```
Lý do tách mã khỏi `TOO_LARGE`: file này **qua được** trần file (19,5 KB < 650 KB) nhưng
KHÔNG phải hoá đơn thông thường ⇒ lời khuyên khác ("gửi file nhỏ hơn" ≠ "file này lạ").
Kèm 2 guard tầng contract: `max_pdf_bytes`/`max_inflated_bytes` khai sai kiểu hoặc = 0 ⇒
`CAPABILITY_CONTRACT_INVALID`; mutation chứng minh sống: `0` · `"650000"` · `"8MB"` đều bị
chặn, còn contract không khai PDF thì vẫn hợp lệ (2 control).
